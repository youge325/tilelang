# Tile Language：简介

## 编程接口

下图展示了 **TileLang** 程序如何从高级描述逐步降级到硬件特定的可执行文件。我们提供了三种不同的编程接口——分别针对**初学者**、**开发者**和**专家**级用户——每种接口位于降级流水线的不同层级。**Tile Language** 还允许在同一个内核中混合使用这些接口，使用户能够在最适合其需求的抽象级别上工作。

## 编程接口级别

1. **初学者级别（硬件无关）**
   - 面向需要编写独立于特定硬件细节的代码的用户。
   - 目标是让开发者专注于基本逻辑，而无需担心内存层次结构或硬件特定的优化。
   - *注意：*该接口尚未完全实现。

2. **开发者级别（硬件感知，配合 Tile Library）**
   - 面向对 GPU 内存层次结构和性能考量有基本了解的开发者。
   - 提供**Tile Library**，包含为各种硬件架构优化的预定义操作和模式。
   - 该级别的用户可以利用这些现成的原语，而无需深入底层线程细节。

3. **专家级别（硬件感知，使用线程原语）**
   - 面向对底层硬件特性（如线程模型、内存合并访问等）有深入了解的高级用户。
   - 提供对**线程原语**和其他底层构造的直接访问，允许对性能关键的内核进行细粒度控制。
   - 该级别为针对特定 GPU 或多核架构的专门优化提供了最大的灵活性。

## 编译流程

1. **Tile 程序**
   计算的高级规范。根据用户的专业程度，他们可以编写纯硬件无关的 tile 程序，也可以从 Tile Library 或线程原语中引入构造。

2. **带 Tile Library 的 Tile 程序**
   当开发者从 Tile Library 中选择时，原始 Tile 程序会被扩展为专门的库调用。这些调用封装了针对不同操作的高效实现模式。

3. **带线程原语的 Tile 程序**
   专家级开发者可以显式使用底层线程构造来手动优化数据布局、同步和内存使用。

4. **IRModule**
   程序与库或线程原语组合后，会被降级为捕获必要硬件细节的中间表示（IR）。

5. **源代码生成（C/CUDA/HIP/LLVM/…）**
   从 IR 中，系统生成目标特定的源代码。该源代码针对期望的后端或 GPU 架构（例如 NVIDIA、AMD）进行了调优。

6. **硬件特定的可执行文件/运行时**
   最后，生成的源代码被编译为硬件特定的可执行文件，准备在相应的设备上运行。该流水线支持多种 GPU 后端，并可扩展到其他架构。

### Tile 声明

我们方法的核心是将 *tile* 作为编程模型中的一等对象。一个 tile 代表数据的一个有形状的部分，可以由一个 warp、线程块或等效的并行单元拥有和操作。在 `Matmul` 示例中，`A` 和 `B` 缓冲区在内核循环内以分块形式（由 `block_M`、`block_N`、`block_K` 决定）进行读取。通过 `T.Kernel`，`TileLang` 定义了执行上下文，包括线程块索引（`bx` 和 `by`）和线程数。这些上下文可以帮助计算每个线程块的索引，并使 `TileLang` 更容易自动推断和优化内存访问和计算。此外，这些上下文允许用户手动控制线程块内每个独立线程的行为。

### 显式硬件内存分配

`TileLang` 的一个标志性特征是能够将这些 tile 缓冲区显式地放置在硬件内存层次结构中。与将其留给编译器的不透明优化过程不同，`TileLang` 暴露了直接映射到物理内存空间或加速器特定构造的用户方面的内部函数。具体来说：

- `T.alloc_shared`：在快速的片上存储空间中分配内存，对应于 NVIDIA GPU 上的共享内存。共享内存非常适合在计算过程中缓存中间数据，因为它比全局内存快得多，并允许同一线程块中的线程之间高效地共享数据。例如，在矩阵乘法中，矩阵的 tile 可以加载到共享内存中，以减少全局内存带宽需求并提高性能。

- `T.alloc_fragment`：在 fragment 内存中分配累加器，对应于 NVIDIA GPU 上的寄存器文件。通过将输入和部分和保持在寄存器或硬件级缓存中，延迟进一步降低。注意，在这个 tile 程序中，每个 tile 分配的本地缓冲区与共享内存相同大小，这可能看起来有悖直觉，因为共享内存通常更快但更充裕，而寄存器文件空间有限。这是因为这里的分配指的是整个线程块的寄存器文件。`TileLang` 在编译期间使用布局推断（Layout Inference）Pass 来推导一个布局对象 `T.Fragment`，该对象决定如何为每个线程分配相应的寄存器文件。这个过程将在后续章节中详细讨论。

全局内存和硬件特定内存之间的数据传输可以使用 `T.copy` 来管理。此外，硬件特定的缓冲区可以使用 `T.clear` 或 `T.fill` 来初始化。对于数据赋值操作，也可以使用 `T.Parallel` 并行执行，如后续章节中布局推断 Pass 的演示所示。
